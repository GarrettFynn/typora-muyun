## 一、立项与调研（起点）

**需求**：把自用 Obsidian 主题 MuYun 慕云「同样地」做成 Typora 主题。MuYun 已上架 Obsidian 社区目录（v0.5.2，三支柱：阅读舒适 / 写作高效 / 快速定位，11 色池降饱和调色板）。

**调研三件事**：

1. **源设计令牌盘点**——通读 obsidian-muyun 的 theme.css，抽出全部设计令牌：纸面（深 #16161D/#1D1D27、浅 #F7F4ED/#EFEBE3）、锚点色（H1 沙金 / H2 慕云紫 / H3 链接蓝 / 加粗金 / 链接蓝 / 灰紫强调）、派生面（边框 / 悬停 / 代码底 / 高亮）、Callout 调色板（蓝紫 / 苔绿 / 慕云紫 / 陶土 / 暗红）、版式（40rem 行宽、0.9rem 段距）、动效纪律（≤200ms、只动 color/opacity/transform）。
2. **Typora 主题机制**——读本机 Typora themes 目录的官方主题（github.css 给选择器全集、night.css 给暗色主题的完整范式：`:root` 内建变量 / html,body 底色 / focus 模式 / 任务框 / 快捷打开 / GFM alerts），确认「`名.css` + `名-dark.css` 成对」的社区惯例，以及 Typora 按文件名 `-dark` 识别深色主题适配铬件。
3. **核心架构决策（此时定下，贯穿全程）**——**深色文件通过 `@import "muyun.css"` 复用全部组件规则，自身只覆盖设计令牌**。单一事实源，深浅两态永不漂移；这也直接决定了后续所有增强「写在共享文件、深色免费继承」的低成本模式。

## 二、v0.1.0：双态初版

**产出**：`muyun.css`（浅色·晨光暖纸，全组件规则）+ `muyun-dark.css`（深色·墨蓝夜空，仅令牌）+ README。

**要点**：

- 令牌双轨：Typora 内建变量（`--bg-color` 等，窗口/侧栏/导出直接吃）+ `--muyun-*` 私有令牌（全部组件规则只消费私有令牌）。
- 组件覆盖：三级标题（H1 金带底线 / H2 紫带 3px 路标条 / H3 蓝）、行内锚点（加粗金 / 高亮淡金 / 标签灰紫淡底）、代码（语法高亮按 MuYun 调色板派生）、GFM 提示块五类（Callout 同源色）、TOC 层级着色、快速打开选中行左条、专注模式弱化、滚动条、打印块（强制白纸黑字——并**在深色文件末尾重申打印块**，因为 `@import` 内容在层叠序上先于深色令牌覆盖，不重申则深色令牌赢过打印覆盖、导出暗底 PDF）。

**验证**：按 Typora DOM 结构搭浏览器模拟页（`#write` / `.md-fences` + `.cm-s-inner` / `.md-alert` / 任务清单等），本地起服务渲染，截图交视觉模型逐项核对——纸面、三级标题、路标条、代码配色、表格、提示块、TOC 三色、复选框，深浅两态全部通过。

**仓库**：讨论后决定独立仓库 `typora-muyun`（与 obsidian-muyun 命名对称；分发形态决定仓库形态：Typora 用户直接下载根目录 css，且为官方主题画廊投稿留路）。双远端发布：公开端 LICENSE 仅署 GitHub ID，私有全量端保留完整署名；公开 main + 私有 private-full 双分支模型（后者 = main + 一条署名提交，之后每次 merge 垫顶）。

## 三、v0.2.0：两批增强 + 实机截图

**第一批（默认生效）**：大纲面板层级圆点（金/紫/蓝，B7 同构）、文件树三件套（文件夹加粗 / 当前项左条 / hover 渐亮 / 缩进引导线）+ 父链高亮（`:has()`，`@supports` 守卫静默降级）；**默认关的注释开关**：S1 表格斑马纹 / S2 图片圆角卡片 / S4 标题自动编号（编辑态即稳定计数——所见即所得无虚拟化，强于 Obsidian 版的仅阅读视图；启用后高特异性规则自动收 H2 路标条）；对比度三档注释预设。

**第二批**：文件列表 / 信息条 tab / 搜索面板输入框、偏好设置与导出面板（导航选中左条）、数学公式配色（TeX 源码取定义紫）、输入光标随交互色（`caret-color` + 源码模式 3px 光标改色）。

**实机截图（本版最大的工程故事）**：CDP 路线被拦——Typora 携 `--remote-debugging-port` 启动时**拒绝创建窗口**（商业混淆构建的反调试行为，裸启动正常、带参无窗口、浏览器级 Target 列表恒空、`Target.createTarget` 报 Not supported）。改用 **Win32 窗口捕获**：PowerShell `SetForegroundWindow` + `MoveWindow` 定尺 + `CopyFromScreen`；第一版截图带桌面杂色边（`GetWindowRect` 含 DWM 阴影不可见边距），改 `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)` 剔除。

**顺手抓到真 bug**：首张深色截图暴露 `kbd` 渲染成白块——Typora 核心样式以更高优先级覆盖了主题的 kbd 规则。修复：`body #write kbd` 提升特异性 + 显式声明文字色，重拍确认。

**其它**：双语 README（Overview / Highlights / 已知差异三段式：做不到 / 反而更强 / 有意为之）、行宽变体 `muyun-wide(-dark).css`（三行文件：`@import` + `--muyun-measure: 46rem`）、打印强化（标题防孤行 / orphans/widows / 表头跨页重复 / `@page` 边距）、模态框与表格编辑工具条。

## 四、v0.3.0 + v0.3.1：深化与第一个规范坑

**v0.3.0**：中西文自动加隙（先在浏览器实测：`normal` 生效 185px vs 关闭 177px）、汉堡菜单面板深化、键盘焦点环（`:focus-visible`）、S4b 编号扩展（默认关）；仓库内容四件——CHANGELOG（Keep-a-Changelog）、PALETTE.md（11 色池 → 变量对照）、`preview/` 双态模拟页入库、release.yml（tag 触发自动挂资产）。

**v0.3.1**：发布工程验证 + 真 bug 各一：

- **workflow 首推漏触发**：tag 与 workflow 文件同推到全新仓库时那次 push 事件被 GitHub 漏掉（零运行）。删 tag 重推即触发——且证实正常路径没问题：v0.3.1 的 tag 推送自动触发、Release 六资产挂齐。
- **`text-autospace: none` 是无效值**：mock 断言发现代码区豁免没生效；规范关闭关键字是 **`no-autospace`**（CSS Text 4），`none` 被浏览器静默忽略回落继承的 `normal`。修复后 A/B 实测：正文 185px（加隙生效）、代码区 177px（豁免恢复）。

## 五、质量工程：五道门禁 + 对比度审计

**`scripts/check-theme.mjs`**（零依赖，`--report` 可出审计表）：

1. 文件齐全；2. 花括号平衡（**剥离注释后**计数——可选开关块里的注释代码含完整花括号，不剥离会误报）；3. `@import` 链可解析 + 变体可达 muyun.css（`night/` 前缀识别为 Typora 内置跳过）；4. **令牌完备性**——深色 `:root` 必须覆盖浅色全部「颜色值令牌」（hex/rgba 启发式区分颜色令牌与 `--monospace` 这类模式无关令牌）；确属「浅色定义、深色有意继承」的走显式 `INHERITED_BY_DARK` 白名单（GFM 提示块色相 5 项）；深色打印块与浅色打印块颜色令牌集必须一致（防暗底 PDF 的自动化版）；`var()` 引用全部可解析（防拼写错）；5. WCAG 对比度门禁（正文 ≥9:1、余项 ≥4.5:1；faint 与深色 H2 为记录项）。

**负向验证**：六种人为破坏（括号失配 / import 目标删失 / 深色删令牌 / 未定义 var / 链接色改到底色 / 打印块删令牌）逐一确认拦截、报错精准，基线与终态通过。其间一次**测试脚本自身的事故**：`cd` 后破坏性 sed 落在仓库源文件上、恢复 cp 在错误 cwd 自拷贝失效——`git checkout` 还原后全程绝对路径重做。教训写进了流程：负向测试永远在临时副本、绝对路径操作。

**对比度审计表**（脚本生成、管道追加进 PALETTE.md，零手抄）：正文实测 10.09 / 10.89:1——「≈10:1 舒适带」主张成立；诚实记录两处：预设档 8.5:1 标称只对深色成立（浅色柔和实测 6.71）、深色 H2 路标条 2.50:1 为双态同值设计例外。

## 七、v0.3.2：大纲色条（真机用户反馈第一例）

**报告**：大纲圆点与标题不对齐；一/二级圆点颜色区分不明显。

**根因**：翻 Typora 安装目录 `base.css` 发现大纲是 **table-cell 布局**（`.outline-expander` / `.outline-label` 均为 `display: table-cell`）——圆点挂在 `.outline-item` 上的 inline-block 在表格行布局里必然错位。当初 mock 页自带 flex 布局把这问题遮住了（mock 与真机 DOM 的偏差第一次现形）。

**重设计（用户拍板）**：圆点改 **14×4px 圆角色条**（呼应 H2 路标条设计语言，更大色面积提升辨识）；挂点移 `.outline-label::before`；深色 H2 色条经新令牌 `--muyun-outline-h2` 提亮 `#525288 → #8383B8`（2.5:1 → ≈4.7:1）——**只提亮导航色条，正文 H2 保持双态同值**，忠于原设计。

**验证**：真机双态截图（临时切深色后还原用户当前选择）+ 视觉核对：对齐 ✓、色条形态 ✓、深色 H2 清晰可见 ✓、金/紫区分明显 ✓。

## 九、v0.3.3：代码块色彩体系（真机用户反馈第二例）

**报告**：深色下代码大面积黑字。

**根因**（枚举安装目录 `codemirror.css` 全部 24 条围栏规则拿到铁证）：Typora 以**与主题同特异性**硬编码浅色系，此前未覆盖的令牌全部泄漏——`cm-variable`（普通变量）与 `cm-property`（对象键名）纯黑 `#000`、`cm-operator` 暗红、`cm-bracket` 暗棕、另有 `cm-variable-3 / cm-quote / cm-hr`。浅色下这套硬编码碰巧协调，问题从未暴露；深色下即黑字。

**修复设计（保持柔和不刺眼）**：

- **基础码色兜底**：代码容器显式 `color: var(--text-color)`——任何未识别 / 未来新增令牌回落正文色，不再依赖继承链；
- **语义归族**（色相全部取自 11 色池）：键名/属性 → 链接蓝族、类型标注 → 沙金族、源码模式引用 → 苔绿族、运算符/括号等**结构符退后取灰**、新增错误令牌 `--muyun-cm-error`（浅暗红 / 深提亮红）；
- 围栏 `cm-s-inner` 与源码模式 `cm-s-typora-default` 双侧同步。

**验证**：真机双态截图 + 视觉逐项核对——深色纯黑文字完全消失、各色柔和不刺眼；浅色无回归。门禁绿（新令牌受双文件覆盖检查约束）。

**收尾同步**：README 代码体系表述更新、PALETTE 语法表 8→12 行、demo 版本头；**三线推送时核出 gh-pages 副本停在 v0.3.1**（在线预览一直带着旧样式）——gh-pages css 副本同步 v0.3.3 并线上验证返回头。

## 附录 B：验证手段演化

mock 渲染（v0.1.0）→ mock + 计算样式断言（v0.2.0 二批）→ 实机 Win32 截图 + 视觉模型核对（v0.2.0 起）→ 打印态注入模拟（收尾批）→ 结构门禁 + 负向破坏（CI 批）→ 真机用户反馈闭环（v0.3.2 / v0.3.3）。**核心经验：mock 通过 ≠ 真机正确**（kbd、大纲两例皆为 mock 布局遮蔽所致）；**计算样式同帧采样 ≠ 最终值**（过渡元素必须等动效结束）。
